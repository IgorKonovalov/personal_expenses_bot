Бот — один процесс на Node 24 со строгим TypeScript. Он получает обновления Telegram долгим
опросом (grammY), хранит данные в SQLite (better-sqlite3) и не зависит ни от каких облачных
сервисов. Выбор стека описан в
[ADR-0001](https://github.com/IgorKonovalov/personal_expenses_bot/blob/main/docs/adrs/0001-tech-stack.md).

## Слои

<Mermaid
  code={`flowchart TB
  TG[Telegram] <--> BOT

  BOT --> SVC[services: сценарии]
  SCHED --> SVC
  FISCAL --> SVC
  STMT --> SVC
  FX --> DB

  JOBS --> STMT

  SVC --> DB[db: SQL и миграции]
  DB --> SQLITE[(SQLite)]`}
/>

- **domain** — чистая логика: деньги, разбор текста траты, временные окна, агрегаты,
  шифрование. Без ввода-вывода, без фреймворка и без чтения часов: «сейчас» приходит параметром.
- **db** — подключение, миграции и репозитории. Единственное место с SQL.
- **services** — сценарии, которые связывают domain и db: записать трату, построить итоги,
  посчитать бюджет.
- **bot** — адаптер Telegram: обработчики, промежуточные слои и модуль текстов. grammY
  импортируется только здесь.
- **fiscal**, **statements**, **fx** — адаптеры внешних источников: чеков, выписок и курсов.
- **jobs** — очередь тяжёлых задач и дочерний процесс для фото и PDF.
- **scheduler** — тик раз в 60 секунд, который запускает итоги, регулярные траты и напоминания
  по местному времени пользователя.

Границы слоёв проверяет линтер: импорт grammY вне `src/bot/`, ввод-вывод или `new Date()` в
`src/domain/` не проходят проверку.

## Правила для всего кода

- Деньги — целое число в минимальных единицах валюты плюс код ISO-4217. Дробных чисел нет нигде:
  ни в хранении, ни в разборе, ни в суммах.
- Моменты времени хранятся в UTC, а «сегодня» и «этот месяц» считаются в часовом поясе
  пользователя.
- Telegram — только адаптер. Внутренний `user_id` — первичный ключ; id в Telegram — внешний
  идентификатор.
- Обработчики идемпотентны: повторно доставленное обновление не записывает трату дважды.
- В логах выше уровня debug нет сумм и описаний.
- Все тексты для пользователя — в одном модуле, на русском.

Учёт (ledger), а не человек, владеет тратами: у каждого пользователя есть личный учёт, у группы —
общий
([ADR-0002](https://github.com/IgorKonovalov/personal_expenses_bot/blob/main/docs/adrs/0002-ledgers-and-identity.md)).
Категории принадлежат учёту
([ADR-0007](https://github.com/IgorKonovalov/personal_expenses_bot/blob/main/docs/adrs/0007-categories-belong-to-ledgers.md)).
